## NibbleNote – Backend

NibbleNote Backend is the core system powering the NibbleNote platform. It is a secure, scalable RESTful API responsible for authentication, authorization, restaurant management, reviews, and analytics.

This repository emphasizes **backend correctness, security, and data integrity**, with a strong focus on real-world production concerns such as token lifecycle management, schema consistency, and API reliability.

---

## Why This Backend Exists

Most review platforms fail at trust. This backend was designed to:
- Ensure reviews are authentic and tied to real users
- Prevent manipulation through strong authentication and access control
- Maintain long-term data integrity across users, restaurants, and reviews

The backend is intentionally built before UI polish to guarantee a solid foundation.

---

## Engineering Focus

- JWT-based authentication with refresh token rotation
- Middleware-driven authorization and route protection
- MongoDB relational modeling (Users ↔ Restaurants ↔ Reviews)
- Schema-level validation and consistency
- RESTful API design with predictable response structures
- API testing and validation using Postman prior to frontend integration

---

## Tech Stack

- **Runtime:** Node.js
- **Framework:** Express.js
- **Database:** MongoDB (Mongoose ODM)
- **Authentication:** JWT (Access & Refresh Tokens)
- **Media Storage:** Cloudinary
- **Maps & Location:** Google Maps API
- **Deployment:** Vercel

---

## Core Features

- Secure user authentication and authorization
- Token lifecycle management (access & refresh tokens)
- CRUD APIs for restaurants and reviews
- Location-aware restaurant discovery
- Protected routes using middleware-based access control
- Structured MongoDB schemas enforcing relationships and constraints

---

## Architecture Overview

- Express.js handles routing, middleware, and request lifecycle
- MongoDB stores normalized collections for users, restaurants, and reviews
- JWT secures protected endpoints
- Cloudinary manages media uploads
- APIs follow REST principles with predictable HTTP semantics

---

## API Design Principles

- Stateless authentication
- Clear separation of concerns (controllers, routes, middleware, models)
- Consistent error handling and status codes
- Defensive validation at both request and schema levels
